## 为什么会有 100 门垃圾

Day 8～Day 22 期间，我写了很多自检脚本（验证删除接口、限流、缓存、批量操作…），
每次都要往数据库插一条测试数据跑一遍，插完就删。

**删除走的是「软删除」**（`deleted_at` 打时间戳，数据行留在表里），
所以这些垃圾**一直躺在库里**，接口看不见（`coursesRepository.js:36`
只返回 `deleted_at IS NULL`），但导出全表就会全出来。

**这是我的问题**：每轮自检插的数据从来没人清理，
现在全堆在这里了。

## 恢复时怎么办

**如果只是为了「环境没了还能重建」**：直接用 `restore.sql` 全部恢复即可，
多出来的垃圾不影响网站运行（它们躺在库里但界面看不到，因为是软删状态）。

**如果想让数据库干净**：恢复后执行

```sql
-- 删掉测试垃圾（先 SELECT 看一眼，确认删对了再换成 DELETE）
SELECT id, name FROM public.courses
WHERE name ~ '测试|验证|自检|限流|回归|频率|复现|干验|检查台|三件套';

-- 确认无误后再删
DELETE FROM public.courses WHERE ... 上面的条件;
```

**⚠️ 别顺手删掉真实的 8 门。** 那 8 门 id 是 `k01`～`k09`。
